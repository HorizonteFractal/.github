# Diretrizes de Contribuição

A Horizonte Fractal acredita no desenvolvimento colaborativo, na qualidade técnica e na evolução contínua de suas soluções.

Este documento apresenta as orientações gerais para contribuir com os projetos mantidos pela organização.

## 1. Antes de contribuir

Antes de iniciar qualquer contribuição:

- Consulte o README do repositório para compreender os objetivos do projeto.
- Verifique as issues abertas para evitar duplicidade de esforços.
- Consulte a documentação técnica e as orientações específicas do projeto.
- Avalie se a alteração proposta está alinhada ao escopo e às necessidades do projeto.

Cada repositório poderá estabelecer diretrizes complementares.

## 2. Tipos de contribuição

São bem-vindas contribuições relacionadas a:

- Correção de erros e problemas técnicos.
- Melhorias de desempenho, segurança e confiabilidade.
- Aprimoramento de funcionalidades existentes.
- Desenvolvimento de funcionalidades aprovadas para o projeto.
- Atualização e melhoria da documentação.
- Testes e identificação de problemas.
- Melhorias na organização e manutenção do código.

## 3. Fluxo de contribuição

Sempre que aplicável, utilize o seguinte fluxo:

1. Identifique ou registre a issue relacionada à alteração.
2. Crie uma branch específica para o trabalho.
3. Implemente a alteração proposta.
4. Execute os testes pertinentes.
5. Revise o código e a documentação afetada.
6. Envie um Pull Request para análise.

Evite incluir alterações não relacionadas em uma mesma contribuição.

## 4. Convenções de código

As contribuições devem respeitar:

- Os padrões de linguagem e formatação adotados pelo projeto.
- A organização e a arquitetura existentes.
- Os princípios de legibilidade e manutenção.
- As práticas de segurança aplicáveis.
- A compatibilidade com as funcionalidades existentes.

Não introduza dependências, abstrações ou infraestrutura sem justificativa técnica e necessidade identificada.

## 5. Convenções de commits

Recomendamos utilizar mensagens de commit claras, objetivas e padronizadas.

Adotamos como referência o padrão Conventional Commits.

Exemplos:

- `feat: adiciona nova funcionalidade`
- `fix: corrige erro de processamento`
- `docs: atualiza documentação`
- `refactor: reorganiza componente`
- `test: adiciona testes automatizados`
- `chore: atualiza configurações do projeto`

As mensagens devem descrever objetivamente a alteração realizada.

## 6. Pull Requests

Todo Pull Request deve apresentar:

- Descrição objetiva da alteração.
- Motivação e contexto da implementação.
- Referência à issue relacionada, quando aplicável.
- Evidências de testes realizados, quando pertinentes.
- Impactos conhecidos sobre funcionalidades existentes.

Pull Requests poderão ser solicitados para ajustes antes da aprovação.

## 7. Segurança e dados

Não inclua nos repositórios:

- Senhas ou credenciais.
- Chaves de API e tokens de acesso.
- Dados pessoais ou informações confidenciais.
- Arquivos de configuração contendo segredos.
- Informações internas sem autorização para divulgação.

Vulnerabilidades de segurança devem ser comunicadas conforme as orientações do arquivo SECURITY.md.

## 8. Documentação

Alterações que afetem funcionalidades, configurações, arquitetura ou utilização dos projetos devem ser acompanhadas das atualizações de documentação pertinentes.

A documentação deve ser clara, objetiva e compatível com o estado atual da implementação.

## 9. Considerações finais

As contribuições serão avaliadas considerando sua relevância, qualidade técnica, segurança, compatibilidade e alinhamento aos objetivos do projeto.

A Horizonte Fractal reserva-se o direito de aceitar, solicitar ajustes ou rejeitar contribuições que não atendam aos critérios estabelecidos.
